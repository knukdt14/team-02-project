# ft_dataset_v3_ksj 학습 가이드

## 1. v3 데이터셋 목적

`data/ft_dataset_v3_ksj.jsonl`은 RAG 검색 결과를 보고 짧고 정확하게 답하며,
실제로 사용한 근거의 `[C번호]`만 인용하도록 Mistral 7B를 QLoRA 방식으로
미세조정하기 위한 데이터입니다.

기존 소규모 데이터에서 특히 약했던 복합질문 대응과 인용 정확도를 보완하기 위해
복합질문을 전체의 40%보다 많이 구성했습니다.

## 2. 데이터 구성

| 유형 | 개수 | 학습 목적 |
|---|---:|---|
| 단일 근거 질문 | 100 | 한 근거로 간결하게 답하기 |
| 방해 근거 포함 단일 질문 | 40 | 관련 없는 검색 결과를 인용하지 않기 |
| 2개 근거 복합질문 | 130 | 두 요구사항에 모두 답하고 두 근거 인용하기 |
| 3개 근거 복합질문 | 60 | 여러 요구사항을 빠뜨리지 않고 답하기 |
| 답변 불가 질문 | 30 | 근거가 없을 때 추측하지 않고 거부하기 |
| **합계** | **360** |  |

- 복합질문: 190개, 52.8%
- 질문 중복: 0개
- 평가 질문과 동일한 질문: 0개
- 평가 정답 조문과 겹치는 학습 근거: 0개
- 존재하지 않는 인용 ID: 0개
- 중간에서 잘린 답변 문장: 0개

## 3. 학습 기본값

| 설정 | 값 | 이유 |
|---|---:|---|
| epoch | 1 | 작은 데이터에 과적합되는 현상을 줄이기 위해 한 번만 학습 |
| learning rate | 5e-5 | 베이스 모델 능력을 크게 훼손하지 않도록 낮춘 학습률 |
| max length | 512 | 질문·근거·정답을 가능한 한 함께 보존 |
| batch size | 1 | 8GB GPU 메모리에 맞춘 값 |
| gradient accumulation | 8 | 작은 실제 배치를 보완 |
| LoRA rank | 8 | 메모리 사용량과 학습 안정성의 균형 |

## 4. 실행 순서

아래 명령은 프로젝트 최상위 폴더에서 실행합니다.

```bat
conda activate SAFETY_RAG_PY311
prepare_finetune_data_ksj.bat
python src\finetune_mistral_qlora.py
evaluate_mistral_qlora_ksj.bat
```

첫 번째 배치 파일은 v3 데이터를 다시 생성하고 검증한 뒤, 학습 스크립트가
데이터를 정상적으로 읽는지 확인합니다.

학습이 끝나면 어댑터는 다음 경로에 저장됩니다.

```text
models/mistral7b_ksj_adapter_v3
```

평가 결과는 다음 이름으로 저장됩니다.

```text
mistral7b_qlora_ftv3_hybrid_ksj.csv
```

## 5. GPU 메모리 부족 시

CUDA out of memory 오류가 발생한 경우 데이터나 epoch를 바꾸지 말고
입력 길이만 448로 낮춰 다시 실행합니다.

```bat
python src\finetune_mistral_qlora.py --max_length 448
```

## 6. 결과를 볼 때 중요한 항목

- `bertscore_f1`: 정답의 의미와 얼마나 비슷한지
- `keyword_rate`: 정답 핵심어를 얼마나 포함했는지
- `hit_at_k`, `recall_at_k`, `mrr`: 검색 단계가 정답 근거를 찾았는지
- `model_citation_f1`: 모델이 실제로 출력한 인용이 맞는지
- `final_citation_f1`: 후처리까지 끝난 최종 인용이 맞는지
- `refusal_acc`: 근거가 없는 질문을 올바르게 거부했는지
- `latency`: 질문 한 건의 전체 응답시간

파인튜닝 효과는 반드시 같은 검색 설정의 베이스라인 결과와 비교해야 합니다.
검색 결과가 같아도 답변·인용 지표가 낮아지면 파인튜닝 데이터나 학습 설정이
생성 모델의 능력을 손상시킨 것입니다.

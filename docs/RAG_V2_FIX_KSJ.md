# RAG v2 성능 문제 진단 및 수정 결과

## 1. 결론

기존 결과가 나빴던 원인은 모델 하나가 아닙니다.

1. 정답 조문이 검색되지 않는 검색 오류가 있었습니다.
2. 정답 조문을 검색했어도 모델이 `[C1]` 형식을 빠뜨리면 프로그램이 정답을
   강제로 “찾을 수 없음”으로 바꾸는 후처리 오류가 있었습니다.
3. 하나의 질문에서 여러 조문이 필요한데도 단일 벡터 검색 한 번만 했습니다.
4. QLoRA 데이터가 작고 반복적이어서 원본 모델보다 거절이 늘었습니다.

따라서 지금은 파인튜닝을 다시 하기 전에 검색과 답변 후처리를 먼저 고쳤습니다.

## 2. 기존 네 실험 결과

| 실험 | BERTScore F1 | Hit@5 | Recall@5 | Citation F1 | 답변 가능 판단 정확도 | 평균 지연 |
|---|---:|---:|---:|---:|---:|---:|
| Mistral 7B 원본 | 0.7123 | 0.6667 | 0.5000 | 0.2222 | 0.2857 | 6.58초 |
| Mistral 7B QLoRA | 0.7122 | 0.6667 | 0.5000 | 0.1389 | 0.4286 | 8.37초 |
| Mistral 자동 이름 결과 | 0.7123 | 0.6667 | 0.5000 | 0.2222 | 0.2857 | 6.34초 |
| Qwen 1.5B 대조군 | 0.6908 | 0.6667 | 0.5000 | 0.0000 | 0.3571 | 2.44초 |

Mistral 자동 이름 결과는 Mistral 원본 결과와 사실상 같은 실행입니다.
QLoRA는 BERTScore가 늘지 않았고, 인용과 속도는 오히려 나빠졌습니다.
현재 어댑터를 최종 모델로 채택할 근거는 없습니다.

## 3. 대표 실패 사례

- 작업중지 질문은 정답인 제52조가 검색 1위였지만 `[C1]`이 없다는 이유로
  프로그램이 정답을 거절문으로 바꿨습니다.
- 사망 처벌 질문은 정답 제167조가 검색되지 않고 제170조가 검색되어
  잘못된 처벌 수치를 답했습니다.
- 안전보건총괄책임자 질문은 제목이 정확히 일치하는 시행령 조문을 놓쳤습니다.
- 단계별 풍속 질문은 제37조·제140조·제143조를 함께 찾아야 하지만
  단일 검색으로 일부 조문만 찾았습니다.

## 4. v2에서 고친 내용

### 검색

- 기존 dense similarity 검색과 한국어 법률용 BM25를 결합했습니다.
- 한국어 조사 차이를 줄이려고 공백 단어와 한글 3-gram을 함께 사용합니다.
- 직책명이 비슷한 문서가 섞이지 않도록 제목 일치 보너스와 불일치 감점을 넣었습니다.
- 사망·처벌, 풍속 단계, 밀폐공간처럼 여러 근거가 필요한 질문은 하위 질의로
  나누어 검색한 뒤 결과를 합칩니다.
- 같은 조문의 여러 청크가 top-5를 모두 차지하지 않도록 출처 단위 중복을 줄였습니다.

벡터 임베딩 자체는 그대로 사용하므로 기존 FAISS 저장소를 재사용할 수 있습니다.

### 답변과 인용

- `[C1]`, `근거 1`, 실제 법령명·조문 직접 표기를 모두 읽습니다.
- 검색되지 않은 조문은 실제 사용 출처로 인정하지 않습니다.
- 인용 형식을 빠뜨린 답변은 삭제하지 않고 `ANSWER_UNCITED`로 보존합니다.
- `raw_answer`를 결과 CSV에 저장해 모델 원문과 후처리 결과를 비교할 수 있습니다.
- 실시간 최신 개정이나 개별 현장 법률판단은 LLM 호출 전에 별도로 거절합니다.

## 5. 로컬 검색 회귀 점검

수정된 검색기를 평가 질문의 정답 조문과 대조한 결과:

| 지표 | 기존 similarity | v2 hybrid 점검 |
|---|---:|---:|
| Hit@5 | 0.6667 | 1.0000 |
| Recall@5 | 0.5000 | 1.0000 |
| Precision@5 | 0.1833 | 0.3667 |
| MRR | 0.4292 | 0.9583 |

이 값은 검색 코드 회귀 점검 결과입니다. 최종 성능은 사용자 컴퓨터에서 실제
FAISS 저장소와 모델로 새 평가를 실행해 확인해야 합니다.

## 6. 지금 실행할 순서

프로젝트 루트에서:

```bat
conda activate SAFETY_RAG_PY311
python src\check_mistral_env.py
check_retrieval_ksj.bat
run_mistral_ksj.bat
```

`check_retrieval_ksj.bat`는 7B 모델을 로드하지 않고 실제 저장된 FAISS의
검색 지표만 빠르게 확인합니다. 그다음 첫 답변에서 확인할 것:

- 정답이 1~3문장인지
- `검색된 근거`의 상위권에 필요한 조문이 있는지
- `실제 사용 출처`가 답변 근거와 같은지
- `인용 상태`가 `CITED`인지, 아니면 `MISSING`인지

전체 Mistral 원본 평가:

```bat
evaluate_mistral_ksj.bat
```

결과:

```text
eval\results\mistral7b_base_hybrid_v2_ksj.csv
```

속도 대조용 Qwen 평가:

```bat

```

QLoRA 재평가는 원본 v2 결과를 먼저 확인한 뒤 실행합니다.

```bat

```

## 7. 채택 기준

아래 순서로 판단합니다.

1. Hit@5와 Recall@5가 개선됐는지
2. 답변 가능한 질문을 불필요하게 거절하지 않는지
3. 실제 답변의 수치·주체·조치가 정답인지
4. used_sources가 답변에서 실제 사용한 조문인지
5. 그다음 BERTScore와 응답시간을 비교

BERTScore 하나만 높아도 법령 답변이 맞다는 뜻은 아닙니다. 틀린 조문이나
거절문도 정답과 단어가 겹치면 점수가 높게 나올 수 있습니다.

## 8. 파인튜닝 판단

현재 QLoRA 어댑터는 사용하지 않는 편이 낫습니다. 먼저 v2 검색과 후처리로
Mistral 원본을 다시 평가합니다. 검색이 맞는데도 문장 생성이나 인용 선택이
계속 틀릴 때만 다음 학습 데이터를 새로 설계합니다.

- 같은 거절 답변 반복을 줄입니다.
- 한 근거 답변뿐 아니라 두세 근거를 종합하는 예시를 넣습니다.
- `[C1]`, `[C1, C2]`를 정확히 선택하는 예시를 넣습니다.
- 평가 질문과 의미가 겹치는 문장은 학습에서 제외합니다.
- 근거에 없는 수치와 조문이 없는지 사람이 검수합니다.
